# 正式卡牌资产管理

日期：2026-11-13。

本目录用于游戏内通用、狂刃、铁壁、蚀毒卡牌。双击同目录的「卡牌资产总览.html」，可离线按路线、卡名、ID 或效果查找素材，切换基础／升级效果，并打开插图或外壳原图。

## 目录与对应关系

- `外壳/`：4 张原始 RGBA PNG，1024×1536，逐字节复制自 `G:\godot\output\卡牌拆分\卡牌模板`。保留透明窗口、内阴影与外阴影。
- `插图/通用、狂刃、铁壁、蚀毒/`：每张基础卡单独一张插图，以「稳定ID_中文卡名.webp」命名。通用20张，其余各12张；每张不超过500,000字节（0.5 MB）。保留1536×1024分辨率，从原图直接编码高质量WebP。
- `卡牌资产映射.json`：游戏读取的正式索引，包含路线、外壳、插图、来源、尺寸、SHA-256 和制作状态。
- `卡牌资产总览.html`：离线素材检索与核对页。文字是映射快照，游戏实际数值始终从 `Game/Resources/Cards/*.tres` 读取。

## 游戏中的使用方式

`CardArtCatalog.gd` 按稳定卡牌 ID 获取素材，去掉升级后缀「+」后复用对应基础插图。`CardArtwork.gd` 先绘制圆角裁切的插图，再叠放原始外壳，最后绘制实时名称、费用、类型、效果和操作提示。整张牌按2:3等比缩放，不能分别拉伸宽高。

原画布：1024×1536。插图底层坐标为 `(114,340,796,454)`，配合圆角遮罩及外壳内沿阴影；请让关键主体处于图片中心安全区。标题、蓝色费用宝石和正文区域保留给程序文字。基础和升级版共享插图，不把文字烘焙进图片。

手牌、奖励、商店、图鉴、卡库、悬停预览和锻造对照共用该组件。原有卡牌ID、效果与存档结构不因美术替换而改变。

## 替换和新增

替换单卡：在生成记录的 `图片元数据/卡牌ID.json` 中更新 `source` 为新的无字横向原图路径，再运行 `ingest`。脚本从原图编码WebP，保持中心构图与分辨率，并更新正式路径、容量、尺寸、哈希和状态。Godot 会重新导入图片。重新生成离线总览后核对基础及升级版。

新增卡牌：先创建规则资源，再在映射中新增同ID记录与独立插图。不要复用其他卡牌的ID，也不要将无关卡牌指向同一张插图。路线字段与规则资源一致。

更换外壳：修改映射的 `shells` 与对应卡牌记录的 `shell`。若外壳结构或画布比例发生变化，需要同步调整组件坐标及遮罩；仅换颜色且结构相同则不需改布局。

## 生成记录与检查

完整生成提示词、逐图原始路径及验收截图保存在 `G:\godot\output\卡牌拆分\正式接入`。本批插图使用内置 imagegen，PNG原图保留在生成目录，正式WebP编码后保存入本项目，不依赖用户缓存路径运行。容量优化记录见 `正式接入/容量优化/插图容量核验.json`。

在项目上级目录执行：

```powershell
python .\余烬十二关\tools\管理卡牌资产.py ingest
python .\余烬十二关\tools\管理卡牌资产.py verify
python .\余烬十二关\tools\生成卡牌资产总览.py
.\Godot_v4.7.2-stable_win64_console.exe --headless --path .\余烬十二关 --script res://tests/test_card_art.gd
```

`ingest` 根据生成记录从原图编码正式WebP，优先使用质量95，必要时逐级调整至每张不超过500,000字节；不缩小分辨率，不使用已压缩图再次编码。若人工换图，请同时维护对应原图记录。脚本仅清理正式插图目录内已被WebP替代的旧PNG，保留外壳和原图。`prepare` 用于初次建档，会重建映射，日常维护无需运行。

完整性核验检查56张插图的容量、解码、尺寸、哈希和4张外壳原样一致性；界面核验检查所有基础／升级卡、等比缩放、文字边界、三种窗口尺寸及图鉴／锻造入口。实机截图见「验收预览」。
