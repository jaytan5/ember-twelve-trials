## 1. 本次确立的方向

**温暖配色、大块圆润造型、清楚的正面与底座、简化卡通材质、粗壮易读的标题文字。按钮看起来饱满、能按下去，面板像一整块有厚度的游戏道具。**

保留用户认可的红、金、棕、奶油色关系。本版以用户提供的《小泥团出击_UI风格规范_v1.0.md》为内容基础，具体主菜单材质色沿用该文档；通用面板补充沿用已认可的米色与棕色。参考作品用于说明美术语言，游戏标题、图标、徽章和布局继续使用本项目设计。

本文件为后续制作的统一依据。旧色卡仅用于查看颜色，旧 V2 卡通立体图保留为探索稿；旧文件中与本版冲突的造型描述不再作为执行标准。本版风格板是概念参考，不是引擎截图或可直接切图的资产。

## 4. 形体与尺寸规则

所有数值是制作起点，按最终逻辑显示尺寸定义，不按 AI 图片像素机械照搬。

### 4.1 按钮结构

从后向前为：投影 → 深色底座 → 彩色正面 → 倒角与金边 → 图标与文字。

- 使用正面视角；只露出适量下侧和右侧厚度，不出现明显俯视或等距透视。
- 以按钮高度 H 为基准：圆角半径约 `0.18–0.24H`；下侧露出厚度约 `0.08–0.12H`；金边单侧可见宽度约 `0.025–0.045H`。
- 例如 `H=64` 的按钮，下侧约 `5–8`，金边约 `2–3` 个逻辑像素。倒角应作为色面表达，不再额外套数层金框。
- 正面上亮下暗，倒角转折圆润；表面略饱满，不做尖锐切边或过度鼓胀的软糖造型。
- 单个按钮最多一个功能图标；不挤占文字安全区，不给每个按钮都加三张卡牌或指南针。
- 主次按钮属于同一形状家族，以颜色、尺寸和图标密度区分层级。

### 4.2 面板结构

- 面板外壳使用圆润棕色框体，内板为奶油米或剧情深棕。
- 以短边 S 为基准，外壳单侧宽约 `0.02–0.035S`，下侧厚度约 `0.015–0.025S`；金属仅作局部包边或护角。
- 大面板不能像放大的按钮，也不需要整圈厚金框。正文区保持平静，避免仿古卷轴、破损纸边和满屏雕花。
- 标题可以是上沿凸起的短红牌；卡牌或指南针徽章按内容择一，小于标题区域，不盖住正文。

| 继续游戏 | 共用主按钮轮廓，面积略小；装饰与反光减少 | 古铜棕＋暗香槟金＋暖白字 |

| 确认弹窗 | 棕色圆润框体＋米色内板；短红标题牌；正文留白充足 | 主确认红色，取消／返回古铜棕或米棕 |

| 设置面板 | 与通用弹窗共用外壳；滑杆槽内凹、滑块凸起；开关状态明确 | 米底＋棕槽＋暖金滑块；红色仅给主操作和选中重点 |
| 奖励弹窗 | 内板平静，奖励图标大而清晰，数量与名称紧邻 | 奶油米＋棕框；金色集中在奖励与徽章 |
| 卡牌／背包格 | 统一圆角、浅倒角和内槽；内容图优先于框体装饰 | 米棕为基础；选中加金边及勾，不只改变色相 |
| 关闭按钮 | 面板右上角紧凑圆角方钮，与框体相连 | 暗红／红底＋清楚的暖白叉；尺寸低于主操作 |

### 5.1 对话框内的排版

- 标题：较粗圆润字体，可有短描边和投影。
- 正文：普通或中等字重，不加挤出；逻辑字号建议 `18–22`，行高约 `1.35–1.5`。
- 主按钮与次按钮并列时使用同一基线；复杂文案不能靠横向压缩字体塞入。
- 正文边距建议 `24–32`，按钮间距 `12–16`；尺寸较小时按可读性调整。
- 列表、长对白优先延展内容区或滚动，不能把所有文字都做成大型卡通标题字。

### 5.2 字体与主菜单尺寸

- 沿用项目已有的阿里妈妈方圆体与 MiSans；标题和按钮通过合适字重体现厚实，不通过变形字宽制造效果。
- 按钮文字逻辑字号建议 `22–28`，深棕描边约 `1.5–2.5`，短阴影约 `1–2`；正文不套用该参数。
- 主菜单延续 v1.0 的紧凑占屏关系：主按钮约 `200×56`、次按钮约 `190×50`；须先换算项目缩放。宽倒角不能成为盲目放大按钮的理由。
- 设置可视尺寸约 `42×42`，热区至少 `56×56`。在 1600×900 逻辑画布上需按既有缩放体系换算，避免把建议值当作所有分辨率的固定像素。

## 6. 材质、光照和阴影

- 红色正面：平滑卡通珐琅，宽而柔和的顶部受光面；无强烈镜面白斑。
- 古铜棕：低反光的简化金属或烤漆；通过大明暗面区分厚度。
- 金色：上亮、侧暗，转角圆润；保留香槟金色相，不出现荧光黄、镀铬银或白色光圈。
- 木材只用于有叙事需求的面板，最多几条宽木纹；不把所有框体都做成粗木箱。
- 暖色左上主光形成统一资产光照；可按场景微调整体色温，不逐屏改变体块受光方向。
- 接触阴影较紧、底座暗面清楚，投射阴影柔和；层次清楚不等于画一圈粗黑边。
- 文字和触控区域不得被装饰、阴影、角色或徽章覆盖。

## 7. 交互状态

| 状态 | 视觉规则 | 建议时间 |
|---|---|---|
| 默认 | 正面隆起、底座清楚、顶部高光稳定 | 静态 |
| 悬停 | 顶部受光面微亮，可放大至 `1.02`；轮廓与材质不变 | `100–140ms` |
| 按下 | 正面下降约 `0.04–0.06H`，底座露出厚度缩短，投影收紧 | `60–90ms` |
| 松开 | 恢复正面位置和底座高度，轻微回弹 | `100–150ms` |
| 焦点 | 独立的金色焦点轮廓或小箭头，与悬停可以同时存在 | 立即可见 |
| 禁用 | 整体低饱和、反光减弱；仍看得出形状和文字，必要时有锁与原因 | 静态 |
| 加载 | 原位置显示小进度图标，按钮宽度不跳变，避免重复触发 | 随任务 |

选中、警告、成功等语义同时配合形状、图标或文案。避免持续闪烁、无操作的循环弹跳和全框发光。

## 8. Godot 资产交付边界

- 正式按钮优先拆为底座、正面、图标和引擎文字；需要时按下只移动正面层。
- 可拉伸框体采用九宫格，保留四角与倒角厚度；装饰图标单独叠放，不能跟随面板整体拉长。
- 背景资源包含可伸缩主体，徽章与固定纹样不得跨越拉伸区域；正文使用真实文本。
- 透明 PNG 必须为真实 Alpha；四周留足阴影空间，报告可视内容边界与切片边距。
- 提供默认、悬停、按下、禁用状态，或明确由引擎完成的位移／亮度参数。
- 风格板中的中文只供概念展示；正式界面以引擎文本确保字形、清晰度和本地化。
- 本次不修改游戏运行脚本、主菜单布局或已使用的资源；落地替换属于后续实施。

## 10. 验收标准

- 缩到实际显示尺寸后，仍能看清按钮正面、底座与主次关系。
- 去掉金属装饰后，形体仍然圆润、厚实、有明确按压感。
- 红色主按钮、棕色次按钮、圆形设置属于同一造型与光照家族。
- 金边为辅，不能比按钮正面或文字更醒目。
- 正文区有足够留白，长对白与设置说明无需粗描边也能读清。
- 一个弹窗只突出一个最高优先级操作，关闭入口不会争夺焦点。
- 同尺寸同状态控件的倒角、侧面厚度、阴影偏移保持一致。
- 不依靠背景插画、发光或繁复装饰掩盖组件本身的造型问题。
- 本版效果图、配色表与实际切片应分别验收；概念图不能视为已完成引擎落地。
